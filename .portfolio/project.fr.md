J'ai créé Workflows pour organiser les tâches d'ingénierie récurrentes en procédures aux objectifs, limites et critères d'achèvement explicites.

Le projet réunit sept skills consacrées à l'orchestration, aux worktrees, aux commits, aux pull requests, aux revues, à la documentation et aux livrables HTML. Chacune peut être installée et utilisée indépendamment.

## Des limites définies pour chaque procédure

Chaque skill guide les décisions importantes pour une tâche donnée. Une revue doit respecter les critères demandés et relier ses constats à des éléments concrets. Une pull request doit expliquer le problème, le comportement obtenu et les vérifications effectuées. Un commit doit regrouper une modification cohérente.

Les instructions permettent aussi de réutiliser le contexte existant et les vérifications tant qu'ils restent valides. Une investigation plus poussée s'impose lorsque des informations pertinentes manquent.

Le package est composé d'instructions et de métadonnées, sans runtime, scripts d'exécution ni hooks qui lui soient propres. L'exécution s'appuie sur les outils et les permissions de l'environnement dans lequel les skills sont installées.

## La responsabilité de l'ensemble de la tâche

Dans l'orchestration, le coordinateur définit les objectifs, répartit le travail, résout les dépendances et vérifie que les résultats répondent à la demande. Les agents chargés de l'exécution prennent en charge l'investigation, les décisions techniques, l'implémentation, l'intégration et la vérification.

Chaque tâche confiée doit préciser le comportement attendu, les limites et le contexte nécessaire. Lorsqu'une livraison est incomplète, le coordinateur décrit ce qui manque et renvoie la tâche à l'agent responsable.

Cette répartition maintient la responsabilité technique auprès de la personne qui exécute le travail. Le coordinateur suit les résultats et les dépendances entre tâches, tandis que l'agent responsable mène le travail jusqu'à son terme.

Workflows peut être utilisé avec Continuity : le premier guide les procédures d'exécution ; le second conserve les connaissances et les contributions entre les tâches et les projets.
