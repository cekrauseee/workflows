# Pull request

For a new description or changed implementation, establish the repository, base, head and complete proposed diff. Reuse current evidence; read commits or templates when they add needed context. Local uncommitted changes are absent from a published PR. A wording-only revision needs the relevant PR text and facts, not a new repository investigation.

Lead with the concrete problem and resulting behavior. Preserve the applicable template and scale detail to the change. Include only verification actually performed and material limitations. Prefer concise English and a Conventional Commit title unless the user or project chooses otherwise; branch and commit types do not determine the PR type.

Drafting is read-only. Publish or update remotely only within the user's request; merging is separate. Before writing, confirm the intended PR or repository and relevant current remote state. Preserve actual newlines. Verify the published content and return its URL.
