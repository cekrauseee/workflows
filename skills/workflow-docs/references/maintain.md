# Maintain documentation

Start from the existing entry point or the files referenced by the changed behavior. Trace each changed assertion to source, configuration, tests, or an explicit decision. Update the narrowest canonical file, including affected commands, diagrams, links, and examples. Keep a confirmed project decision in its relevant document; do not add raw investigation logs or conversation history.

When a topic outgrows its page, split by reader need and route to the new page through the project's existing navigation. Size alone does not justify splitting. Remove stale duplicates within the authorized scope instead of leaving two conflicting instructions. Preserve generated documentation workflows: update the source and run the relevant generator rather than editing generated files alone.

Check changed links with the bundled checker. Use the project's documentation build or lint checks where required and available. Browser or visual QA is optional unless requested or required by the task; report a material gap rather than implying it was performed. For missing credentials, verify configuration handling and offline behavior without inventing live verification.
